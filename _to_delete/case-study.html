What the first version got wrong

The first build looked finished. Glass card, animated rain, a progress ring, two colour modes that swapped on a three second transition. Screenshot it and you would call it done.

It was not done. I opened it in a browser, measured the live DOM instead of trusting my eyes, and found fourteen defects. Several were invisible in a screenshot and obvious in a number.

The headline failure: the three second colour fade I was proudest of never executed a single frame. CSS cannot interpolate between two linear-gradient() values, so the browser skipped the property entirely. I had been looking at a hard cut for weeks and reading it as a fade because I knew what it was supposed to do.

That is the argument for measuring. Familiarity with your own work is the thing that stops you seeing it.

Three that mattered

Cross-fade two layers instead of one property

Gradients are not interpolable, so the fix was structural rather than a tweak. Two stacked layers, each holding one palette, cross-faded on opacity. Opacity is compositor friendly, so the fade costs nothing on the main thread.

The ink crosses on the same clock. Flipping it at frame zero left the timer unreadable mid-switch.

Break mode flips the ink, not the background

The instinct is to darken the warm gradient. That kills the feeling the mode exists for. Instead every colour became a token, and break mode redefines the token set to dark ink on a stronger card tint. Same warmth, readable text.

Worst case moved from 1.18:1 to 5.32:1. Best case reads 11.96:1.

Session 1 of 4

Trust the clock, not the tick

The original decremented a counter once per interval. Browsers throttle inactive tabs to roughly one tick a minute, so a 25 minute session run in a background tab could finish minutes late, which is the one thing a focus timer cannot do. The rebuild stores a wall clock deadline and derives the remaining time from it on every tick. Throttling now costs display smoothness and nothing else.

What I would do next

Long break after the fourth session

The counter says "of 4" and nothing happens at four. That is an incomplete feature, not a bug, so it did not go in this pass.

Generate the rain instead of shipping it

25MB of audio for ambient noise is indefensible. Filtered noise through the Web Audio API would weigh nothing and sound better.

Test with people who are actually working

Everything here is measurement. None of it tells me whether the rain helps anyone concentrate, which is the only question that finally matters.
